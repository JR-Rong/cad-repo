# 机器 A 启动提示词

你负责本计划机器 A，主责 电机与传动机械接口。目标是本机归属的 42000 个最终接受且全局去重的新零件，候选预算上限 70000；五机合计 210000。这个数量是有条件规划，没有证明存在 21 万个独特架构。本机当前已接受量须盘存，不能初始化成 0 或照抄其他机器数字。

参考仓库 https://github.com/JR-Rong/cad-repo ，文档目录 docs/integrated-workflow-v3；调查基线 commit bdaab3c1de90723fcd07ddae1edc75132b285a09。运行前重新核实本机实际版本及差异，不自动 pull 到正在工作目录。本提示词本身不启动远端机器。

旧分工每机 100 族 ×400 配置的数量承诺取消；旧 key、ID、在途和证据全部保留。本机新建议负责 96 个原目录入口及 10 个待探索子族，族数不等于架构数。主责是承载、轴定位、传力、防护和装拆的机械结构。排除：流体分配排泄给 E；通用机架吊装给 D；干式电子封装给 B；精密工件夹检给 C。以主要功能合同裁决跨域一体件，只有一个 owner。

归属迁移先标记 PENDING_OWNER_ACK；旧 owner 继续负责已领取 revision，双方排空/暂停并核对后只迁移未领取候选。不得因本提示词改动正在生成的任务。转入：st08 带传动张紧支架 原 D。转出：md42 吊装横梁 至 D; tr24 润滑分配块 至 E; tr25 注脂嘴座 至 E; tr42 通气过滤器座 至 E; tr43 排油阀座 至 E。

## 工作方式与第一轮交付

本提示词是准备交接的执行合同，不表示五机整合已经落地。默认 MODE=AUDIT_ONLY；只读盘存、输出明确的恢复计划。只有当前操作者明确授权对应实施/样件/受限批次且下列阻断均有当前版本证据关闭后，才进入该阶段；不得因拿到这份提示词就覆盖生产代码、升级插件、重启现有 runner 或批量生成。不要访问凭据，不把本机数据库、私有日志或大模型产物推入公开 GitHub。

先定位本机 REPO_ROOT、CAD_ROOT、安装插件、LEGACY_SOURCE_ROOT、LEGACY_ARCHIVE_ROOT 和工件存储。检查仓库 remote、branch、dirty、commit 与实际安装源码/发行包/规则哈希，读取 WORKFLOW.md、WORK-ORDER.md、shared/LESSONS.md、shared/versions.json、对应旧 brief 和本版手册。检查旧目录和同名工作区；不能假设本机为空。不要把 git main 最新内容和运行中进程已加载的版本混为一谈。

盘点已有代码、合同、intake、任务、项目、成品、在途、失败、人工待审、registry、发布和全局回执。检查进程与锁 holder 的存活，不删除未知锁，不启动第二个 runner。SQLite 用主库和 WAL 的一致副本只读查询，复制前后核对源哈希；变化则重试或报告不一致，不能让只读盘存迁移生产库。不要调用有副作用的 cad_freecad status、memcheck、board，也不要把 fleet_runner --dry-run 当纯只读。只能读取配置白名单，不回显任何密钥或用户会话正文。

对每条记录保存 canonical/alias、旧 ID、family、owner、batch、revision、输入/源码/规则/Native/STEP/八图/图纸哈希、build/export/probe/validate/package 的原始状态、失败证据、review、published、lease 和全局接收回执。UNKNOWN 必须保留 UNKNOWN；没有 job 行不证明没做过。生成 machine_inventory.json、resume_plan.md 和 blocker_report.md 到新的审计目录，报告跳过、补导、复验、补审、续打包、设计修复、新候选、UNKNOWN 各数与证据。

本机安装和仓库 tgz 同称 0.5.0 却存在源码/规则分叉；安装版 rules_sha=64a95367ef997904，旧签发版=1d835a8f3d2ef4f1。必须记录实际版本并由协调者冻结一个经过验证的版本，不能悄悄修改或自签放行。现有仓库不含已确认完整的原 PartDesign 后端和五机 family_src，先取得源码、引用和依赖，不要猜路径或复制空占位核心。

N45 未解决：同一产物 revision、参数 cell 和窗口中的有效 FAIL 不能被后续 DONE/PASS 或其他窗口覆盖。保留原始 frame、事件身份和失败；只有真实修复的新 revision、完整复验和关闭记录才可解除。旧 release 的 N43/N44 与安装版不同，修过 N44 不代表 N45 已修。先做重复 DONE、FAIL→DONE、跨 cell、子进程异常负例回归；不得篡改历史日志。

原流程要求完整 PartDesign 构造历史、单 Body、真实贡献 sketch/feature；现有 CadKit 常产 Part::Extrusion/Cut/MultiFuse 图。Part:: 有依赖图不自动等于 PartDesign 语义合格，必须选定并实现兼容后端及独立检查适配。strict/require_review 当前默认不是强制；统一入口必须显式要求硬审和实际人工视觉，验证“缺配置/缺审查就阻断”。strict_bop 的 bool 字符串陷阱也须验证。不能以 warnings、run_mode=review 或 package 成功代替门禁。

全局去重当前 SQLite 优先会遗漏 JSON 基线；粗指纹和 merge_check 不能直接证明原图/BRep 独立性。必须接入原 108、DSH 历史、五机已接受与在途的身份并集并验证。缺历史库、恢复器不能识别 package-only/过期输出、租约不明、依赖非零退出却误报 OK，均停在盘存/实现计划。自动或人工说“应当修了”不是关闭证据。

## 复验续作与接受口径

先按现有证据分流，只补缺：已接受且全部哈希/版本有效者跳过生产；技术通过视觉待审者补实际八图审查；只缺 package 者仅恢复该阶段；STEP 或图像依赖 Native 已变化则补导并失效下游；设计失败保留旧 revision 后有预算修复；未知状态先调查。不得清空数据库、覆盖旧 Native、删除失败、重新编号清预算或无依据回填 PASS。

原 100 个新件与 8 个参考件是不同来源类别，作为历史基线，不计入这次 210000 新增目标；DSH 的 delivered、counts、published 不等于最终接受。family 数、结构架构数、配置数、generated、technical_pass、visual_pending、accepted_unique_new、published、delivered 分开报告。尺寸、镜像、改名、孔数网格、无功能筋条或填充段不能充当新架构证明。候选 70000 是预算，不是一次 emit 指令；60% 接受率只是算术情景。

每件须原创正向设计，完整可编辑历史、单 Body 有效闭合正体积实体、1–20000 mm、至少 20 个真实贡献 sketch/feature 节点（不是 20 个实体操作）；STEP 往返相对体积差 <=1e-4、各轴包围盒长度相对差 <=1e-3；关键尺寸 ±0.25% 编辑后恢复；八张 2000 像素视图；FCStd、STEP、必要引用、项目信息、manifest 和版本绑定证据。以上是历史工程阈值，与采购 PDF 的 40 项/32 必选分开映射。可选二维图是原第三章加分项，不冒充每件必备。旧包实际 93 套图纸（85 新+8 参考），15 新件缺图纸。不得声称原 19 检查已覆盖全 40 项。

功能验收检查通道连通/隔离、端口角色、量规自身有效、真实材料接触、阻挡和泄漏；结合 P001 肋挡孔、TC/RC 工具空腔重叠、RF 量规断开、CA 量规落在空腔、QC/HS 参数依赖失败建立真实负例。VH、DP、CY 仍挂起排除。修改检查适用范围须披露版本、原因和保留失败负例，不能降低阈值换 PASS。八图须人真实查看并绑定产物哈希；模型可辅助，不代签人工接受。保持 manufacturing_release=false，不宣称材料、耐压、寿命、制造可用已经认证。

## 全局登记与并发边界

复用现有 intake、fleet_runner、SQLite job/delivery 和 shared/fingerprints。统一验收、接收索引和租约适配仍是待实现，不新建平行调度系统。A 的协调角色初期作为唯一全局接收写入方，A 生产也同等受审；各机只回传自己的 registry delta，不合并或覆盖别机 SQLite。新 ID 建议 f3_<machine小写>_<family>_<六位序号>，revision 单列；先全局占号，旧 ID 永久保留 alias。候选 owner 变更不改变 canonical，不重复计数。

每次领取绑定 canonical、revision、owner、lease token/到期时间、合同和源码哈希。确认并发原子性负例，同一候选只能有一个有效租约；单个 lock 文件或 git push 本身不证明原子性。未知/过期租约先核查执行和产物再恢复。全局接收方用相同基线 revision 做 Native 特征图及 BRep 去重，粗筛必须证明不漏缩放、镜像和跨族重复。离线/基线不全只能保存已授权在途，不增加最终接受数。

最终接受是同一 revision 通过技术、功能、全局去重和人工视觉后的 canonical 唯一接收事件；发布/复制 outbox 是后续事件。失败事件不可被最后一条 DONE 抹掉。视觉待审与 reserved 占容量，接受只计一次；五机本地计数不能直接相加。配额余额由同一全局账本计算，到 210000 停止新领取；验证 N−1→N 仅增一、N 后新生成零及历史 hash 不变。

## 有界修复与阶段扩产

建议设计预算含首次最多 5 次，原“最多重试五次”语义须在生产合同确认，未确认不要自行解释成无限轮。设计修订、阶段重跑、网络重连、probe 窗口分别计数，跨机器和队列不清零。达到预算仍失败置 HELD，保留全部证据。同一根因连续 3 次失败暂停相关族调查。每次推理任务简单分级：低难度自有 API、中等 DeepSeek 官方、困难 Codex；路由及 Qwen 修复闭环当前未整合。无模型权限或端点缺失则 UNKNOWN/阻断，不读取密钥或冒称调用成功。

完成阻断与恢复计划后，按授权分阶段：每机 1 件完整闭环，再累计 5 件跨至少两子族，再累计 25、100；之后单批最多 500，前两波稳定且全局接收无积压才允许单波最多 2000。已有合格证据可抵扣阶段工作，旧 2000 项 scaffold 不自动允许扩产。每个新族先单件，新引擎/核心/规则版本重新验证影响范围。初始每机一个构建任务，package 全生产根单槽；probe 并发按 p95 内存实测，不照抄 workers=3。

人工待审初始上限建议每机 25，达到后先补审；出现未知锁、丢失 FAIL、哈希异常、缺基线、资源不足、OOM 未清理或重复发布即暂停新领取。磁盘按试点单件 p95、在途和一次完整备份预留。降并发不能降图像、缩减 probe 覆盖或跳硬审。总候选预算350000若不足则报告可行性缺口，不能放宽独特性凑数。
